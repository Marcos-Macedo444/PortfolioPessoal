## A identidade do portfólio

Chamei o conceito de **Conexões em movimento**. Na primeira tela, incorporei o **Hyperspeed do React Bits**, com uma pista em perspectiva e trilhas azuis e verdes. Antes dela, o **Encaixe MM** monta minha marca oficial com conexões que chegam das bordas da tela; o espaço entre os dois Ms se abre para revelar o site. Depois da apresentação, um cabo azul forma minhas iniciais **MM**, se transforma em um nó tridimensional de três lóbulos e se desenrola até a linha da minha trajetória. A rolagem natural controla o percurso, inclusive no sentido inverso. Os trabalhos ficam na seção Projetos, sem nomes ou links duplicados na cena. As descrições de Redes, NOC, Segurança e Automação estão preservadas no Repertório técnico.

O azul organiza as rotas e as ações; o verde marca os sinais e a seleção. O tema **Azul**, padrão mesmo quando o dispositivo usa modo claro, combina `#09121E`, `#4C8DFF`, `#65F5A2` e `#E7EEF8`. O **Branco** usa fundo branco, texto escuro e fios azuis com contraste próprio. São as duas escolhas manuais, salvas no navegador pela chave `mm-theme`. Escolhas antigas explícitas continuam válidas; ausência, valor inválido ou o antigo modo automático voltam ao Azul. A troca não recarrega a página nem reinicia a abertura ou a posição da rolagem.

O Hyperspeed usa Three.js diretamente, sem iframe ou vídeo. Meu nome, cargo, apresentação e links continuam em HTML. A entrada usa SVG e CSS, preserva as proporções e os pontos de cor do meu Monogram e dura aproximadamente 4s com o hero disponível, com mais tempo para observar a marca já montada; não criei outro núcleo 3D. A sequência termina automaticamente, sem botão de pular, com limite de segurança independente de 4,4s e reprodução apenas na primeira entrada da sessão. Escape, Tab e mudança de foco ou navegação continuam liberando a página. Âncoras e retorno pelo histórico dispensam a sequência. A navegação mantém a rolagem nativa, pausa global e movimento reduzido. As decisões estão em [DESIGN.md](DESIGN.md).

No celular, a pista é compacta e aparece na abertura, com resolução e densidade controladas. Até 700px, simplifiquei a sequência seguinte para dois quadros no fluxo: chegada e assinatura, seguidas da passagem para a trajetória. O nó fica apenas na versão desktop, sem reservar espaço nem desenhar um quadro oculto no celular. Construí os fios com Canvas 2D, geometria em profundidade e projeção em perspectiva, sem outro motor 3D. Nos cruzamentos do nó, a profundidade determina qual trecho encobre o outro, inclusive o pulso verde que passa atrás do cabo. O renderizador só é solicitado quando começo a rolar até a seção. Com pausa, movimento reduzido, Canvas indisponível ou sem JavaScript, ficam o MM e a passagem visual estáticos. O conteúdo e os links reais continuam em HTML. O efeito-base da primeira tela tem autoria do React Bits: registrei o commit usado, a licença e minhas adaptações em [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Stack

Next.js 16, React 18, TypeScript, Tailwind CSS, Framer Motion, Three.js e Lucide. Acrescentei somente Three.js 0.180.0 e os tipos correspondentes para a cena, seguindo a versão da base consultada. O envio de e-mail usa a API do Resend no servidor. A hospedagem está vinculada à Vercel e ao GitHub.

A tipografia de títulos é Space Grotesk, hospedada localmente. A licença SIL OFL acompanha a fonte em `public/fonts/OFL.txt`. Os textos usam fontes de sistema. Fonte, shaders e módulos da cena são servidos pelo próprio site, sem CDN, modelos ou texturas externos.

## Desenvolvimento local

Uso Node.js entre 20.11 e 24, conforme `package.json`.

```bash
npm install
npm run dev
```

O endereço padrão é `http://localhost:3000`. No Windows, `npm.cmd` pode ser usado quando a policy do PowerShell bloquear `npm.ps1`.

Para validar e executar uma versão de produção:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run start
```

O comando `npm test` usa o runner nativo do Node para verificar a entrada de 4s sem botão de pular, a sessão, a saída por teclado/foco antes da hidratação, movimento reduzido, storage indisponível, padrão Azul e saída de segurança. Também verifico os oito segmentos do Monogram oficial, a amostragem dos fios, a continuidade entre os atos, a reversibilidade, os cruzamentos do nó com separação de profundidade, a oclusão e a saída para a trajetória em diferentes larguras. O runner `scripts/next-runner.cjs` normaliza caminhos do Windows e recria `.next` ao iniciar dev ou build. Por isso, encerro o dev antes de preparar um build e iniciar `start`. A rodada atual está em [docs/refinement-validation.md](docs/refinement-validation.md). Os relatórios de [Conexões](docs/connections-validation.md) e [Hyperspeed](docs/hyperspeed-validation.md) preservam as validações históricas.

## Formulário de contato

O formulário está em `src/components/sections/Contact.tsx`. Ele envia JSON para `/api/contact`, valida os campos, mostra estados de envio e mantém honeypot e cooldown. A rota em `src/app/api/contact/route.ts` valida novamente, escapa o conteúdo HTML e chama o Resend somente no servidor.

Variáveis de ambiente:

```env
NEXT_PUBLIC_SITE_URL=https://marcosmacedo.dev
RESEND_API_KEY=
CONTACT_TO_EMAIL=marcosfilipe.macedo@gmail.com
CONTACT_FROM_EMAIL=
```

Configuro os valores reais em **Vercel > Project Settings > Environment Variables**, no ambiente adequado. A chave do Resend nunca recebe prefixo `NEXT_PUBLIC_`. `CONTACT_FROM_EMAIL` deve ser um remetente autorizado no Resend. Para testar localmente sem enviar e-mails, posso usar `CONTACT_FORM_DRY_RUN=true`; essa opção deve ficar desativada em produção.

Mantenho `.env` e `.env.*` ignorados no Git. `.env.example` é apenas um modelo sem segredos. A resposta de sucesso da API confirma aceitação pelo serviço; recebimento na caixa de entrada é uma confirmação separada.

## Segurança e publicação

Os headers em `next.config.mjs` incluem CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` e `X-Frame-Options`. `unsafe-eval` só é permitido no modo de desenvolvimento do Next/React. Produção continua sem essa exceção. O relatório `docs/firewall-audit-report.md` registra a auditoria anterior; ele é histórico e não representa garantia de liberação em firewalls corporativos.

O fluxo de produção existente usa a `main`: após validação e integração autorizada, um push dispara a Vercel. Branches de trabalho podem receber previews conforme a integração. Os resultados desta entrega, medições de laboratório e limitações estão em [docs/redesign-validation.md](docs/redesign-validation.md).

Capturas locais desta revisão ficam em `.tmp/refinement`, ignoradas pelo Git, assim como as rodadas anteriores em `.tmp/redesign` e `.tmp/connections`. Não publico caches, traces, segredos ou screenshots temporários no repositório.
